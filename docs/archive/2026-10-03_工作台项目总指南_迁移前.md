## 4. 第一版产品结构与目标使用流程

本节描述**目标体验**；实际菜单和按钮名称应随实现更新。当前不能声称所有流程已可用。

### 4.1 界面蓝图

| 区域 | 目标内容                                                                        |
| ---- | ------------------------------------------------------------------------------- |
| 专注 | 番茄钟 / 正计时切换、关联任务（可选）、清晰的运行/暂停状态、开始/暂停/继续/结束 |
| 待办 | 新建、编辑、完成、恢复、删除任务；查看未完成和已完成；从任务进入专注            |
| 统计 | 全历史累计三指标；周视图、月视图；当前期间三指标；前后期间切换及返回本周/本月   |
| 设置 | 番茄时长、休息规则、提示设置；显示统计时区；其他设置沿用并验证上游能力          |

累计与期间数据必须明确标注。例如“累计专注次数”对应全历史，“本周专注次数”对应所选周。不能在同一组三指标中混用全历史次数和本周时长。

### 4.2 目标使用指南

1. **整理待办**：新建任务，填写名称。完成后可标记完成；误标可以恢复。
2. **开始番茄钟**：选择任务或不关联任务，设置本次专注时长并开始。暂停不累计专注时间；继续后仍为同一次专注。自然完成后保存本次专注，再按设置进入休息。
3. **开始正计时**：切换到正计时，从零开始。可以暂停、继续；结束时保存本次有效专注时间。
4. **提前结束**：选择“结束并保存”或“放弃本次”，取消操作则继续原状态。番茄钟提前保存是一次专注，但不是一次完整番茄。
5. **切换任务或模式**：先处理正在进行的会话。未处理前不能把同一会话悄悄归到另一任务或模式。
6. **查看统计**：查看累计三指标；在周/月视图中选择期间，查看每日分布、当期次数、总时长及平均时长。点击有记录的日期查看对应记录，至少能核对时长和归属。
7. **关闭与恢复**：关闭前明确说明是否继续在托盘运行或完全退出。完全退出/异常中断后的未结束会话，在下次启动时提示恢复、保存已记录时间或放弃；不得静默把离线时间计入专注。

## 5. 计时和统计的执行默认

这些规则是 Codex 为消除歧义提出的初始方案。实现方案必须引用对应 D 编号，用户修改时保留决定记录，并更新受影响的测试预期。

### 5.1 一次专注如何定义

| 编号 | 默认规则                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------- |
| D01  | 一次专注从一次开始操作到自然完成或“结束并保存”为止；它有稳定、唯一的 `sessionId`                   |
| D02  | 暂停/继续、路由切换、窗口最小化产生的追踪分段，不创建新的逻辑专注次数                              |
| D03  | 有效专注时长是运行段的实际累计时间；暂停、休息、空闲不计入；不使用“回调执行次数”当作时间           |
| D04  | 番茄钟自然完成只保存一个记录；提前结束并保存按实际运行时间保存，也计一次专注，但完整番茄次数不增加 |
| D05  | 正计时结束并保存计一次专注；没有固定结束长度；界面超过一小时不得溢出或归零                         |
| D06  | 放弃/重置本次不计次数和时长；必须明确告知会放弃，或先提供保存选择；零有效时长不计入                |
| D07  | 未结束会话只显示实时计时，不混入已保存统计；完成持久化后才纳入统计。失败须提示并可重试             |
| D08  | 任务关联可为空；没有关联任务也算专注。开始后任务归属固定；切换要先保存/放弃当前会话                |
| D09  | 第一版单一活动计时器；连续点击、多个窗口或重复启动不得创建并行专注或重复完成记录                   |

基础番茄参数建议沿用常见的 25 分钟专注 / 5 分钟短休息 / 15 分钟长休息，每 4 次完整番茄进入长休息；默认关闭自动开始下一次专注。参数均应可调整。本规则是初始执行默认，不是用户已经指定的数值。

### 5.2 三指标计算

对统计范围 P，取集合 F(P)：符合 D01—D09、已经保存、有效时长大于零、且归档日期属于 P 的逻辑专注记录。

```text
专注次数 N(P) = F(P) 中不同 sessionId 的数量
总专注时长 T(P) = F(P) 中每次有效专注时长之和
平均每次专注时长 A(P) = T(P) / N(P)，当 N(P) > 0
```

- 空集合：次数 `0`，总时长 `0`，平均 `0`（可显示为 `00:00`）；不得出现 NaN、Infinity 或空白误导。
- “累计”使用全部有效已保存记录；所选周/月的三个指标使用同一过滤后的集合。
- 时间底层以整数毫秒保存与计算，最后一步格式化到秒。不得先把每条记录舍入为分钟再求和或平均。
- 展示时按秒四舍五入；总时长可用“小时 分钟 秒”，平均使用 `MM:SS` 或 `HH:MM:SS`。验收同时核对原始值与格式化结果。
- 若保留“完整番茄次数”，单列显示，只计自然完成的番茄钟；不能冒充“专注次数”。
- 同一个 `sessionId` 重复保存须幂等，不得重复增加次数或时长。两个真实独立会话即使任务、模式和时长相同也必须分别计数。

### 5.3 周、月、跨日和时区

| 编号 | 默认规则                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------- |
| D10  | 自然周从周一 00:00 到下周一 00:00；可查看前后周；不是最近 7 天                                     |
| D11  | 自然月从当月 1 日 00:00 到下月 1 日 00:00；支持 28/29/30/31 天；不是最近 30 天                     |
| D12  | 每次专注整条归入结束日期所在的日/周/月；不拆分跨午夜会话，保证次数、总时长和平均口径一致           |
| D13  | 时间戳保存为 UTC 时间；统计按应用的统计时区转换。首次采用 Windows 系统时区并保存，界面能查看该时区 |
| D14  | 若之后修改统计时区，明确提示日期归属会重算；同一统计视图的全部记录均用同一时区，不能混用           |
| D15  | 日期范围使用左闭右开区间 `[开始, 下一期间开始)`；使用当地日历边界，不能假设每个本地日固定 24 小时  |

例如周日 23:50 开始、周一 00:10 结束的 20 分钟专注，整次归周一所在的新一周。这样前一周的这次记录为 0，新一周是 1 次 / 20 分钟 / 平均 20 分钟。

如果用户更重视每日实际时间分布，可改用跨日分摊方案；这会影响平均指标与计数归属，必须先决定并整体更新公式和用例，不得只改图表。

### 5.4 后台、退出与休眠

- Windows 正常后台/最小化/托盘运行继续计时，用可靠时间源校准。界面刷新回调只负责刷新显示。
- 暂停期间停止增加有效时间；保持同一 sessionId。
- 休眠、关机、崩溃或完全退出中断：保存状态检查点，默认不把无法确认的离线间隔计入有效时间；恢复时展示待处理会话，须由用户选择继续、保存已记录时间或放弃。
- 常规运行每不超过 5 秒保存恢复检查点，暂停/继续/结束立即保存；异常终止后最多损失最近 5 秒已运行时间。持久化失败必须有可见提示。
- 正计时不应被普通计时 UI 的最大分钟值截断。番茄自然完成最多登记一次，不因后台延迟回调自动补造多个完成番茄。
- 修改系统时钟时不产生负时长或突然多计数小时；使用单调时间与墙钟/恢复状态配合，并有异常检测。

# 第三部分：验收指南

## 11. 验收环境和判定方法

- 主环境是 Windows 本地桌面应用，报告中记录系统版本、应用身份、实际统计时区及构建版本。
- 先建立隔离测试数据，不操作用户的真实数据库/存储。通过本轮测试接口或隔离存储导入固定数据；测试接口不能以危险形式暴露在正式版本里。
- 工程检查、数据检查和真实交互都要有证据。需要运行的项未执行，就写“未验证”，不能写“通过”。
- 常规计时准确性：连续前台运行 10 分钟、正常后台运行 10 分钟，各与独立时钟比较，显示累计误差不超过 2 秒；暂停一分钟后有效时长增加不超过 1 秒。独立计时不能使用同一个应用实现作为参考。
- 用可控制时间的自动化测试覆盖一小时、跨日、月长、夏令时及异常系统时间，不强迫用户等待数小时。另至少真实完成一次短番茄及一次正计时，并实测暂停和后台。
- 桌面展示至少检查 1280×800 和 1024×768；窄窗口检查 390×700 以及基线允许的最小窗口 340×470；Windows 100% / 150% 缩放检查主要控件。
- 页面能滚动是可接受的，但关键按钮必须可达；页面整体横向溢出、遮挡或无法关闭弹窗属于缺陷。保留上游小窗时，小窗控件也要实际操作。

4. 记录每项通过/失败/未验证，给出缺陷复现、期望结果及建议修复范围。
5. 将结果写入第二轮记录和本文件状态，不直接以第一轮截图或执行者声明作通过依据。
